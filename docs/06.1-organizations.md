# Talnova Onboarding

# 06.1 — Organizations Collection

**Collection Name**

```text
organizations
```

---

# Purpose

The Organization document is the root aggregate of every tenant.

Every employee, onboarding journey, knowledge article, upload, notification and report belongs to exactly one organization.

The Organization aggregate stores:

* Workspace information
* Branding
* Departments
* Teams
* Job titles
* Office locations
* Workspace configuration
* Notification settings
* Security configuration
* Analytics snapshot
* Metadata

This aggregate should be loaded immediately after authentication and cached for the current session.

---

# Collection Overview

One MongoDB document represents one organization.

```text
Organization

├── Workspace
├── Branding
├── Departments[]
├── Teams[]
├── JobTitles[]
├── Locations[]
├── NotificationSettings
├── SecuritySettings
├── InviteSettings
├── Analytics
└── Metadata
```

# Embedded Documents

The following objects are embedded because they never exist independently:

* Branding
* Departments
* Teams
* Job Titles
* Locations
* Workspace Settings
* Notification Settings
* Security Settings
* Analytics

---

# References

The Organization document does not directly embed employees or journeys.

Relationships are maintained through `organizationId` references in other collections.

# Lifecycle

1. Organization created.
2. Owner user created.
3. Default departments inserted.
4. Default settings generated.
5. Employees invited.
6. Journeys created.
7. Analytics updated continuously.

---

# Future Extensions

The Organization aggregate is designed to support:

* SAML SSO
* SCIM Provisioning
* Multiple workspaces
* Custom branding
* AI configuration
* Webhooks
* Billing
* Enterprise integrations
* Marketplace
* Feature flags

These capabilities can be added without changing the overall document structure.
