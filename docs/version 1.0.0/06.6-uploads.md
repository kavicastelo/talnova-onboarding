# 06.6 — Uploads Collection

**Collection Name**

```text
uploads
```

---

# Purpose

The Uploads collection manages all media assets stored in Cloudflare R2.

The platform never stores actual files inside MongoDB.

MongoDB stores only metadata and references while the binary files remain in Cloudflare R2.

This architecture provides:

* Lower database costs
* Better scalability
* Faster backups
* Better CDN performance
* Large file support
* Easier media management

# Upload Flow

Step 1:

```text
Client Requests Upload URL
```

Step 2:

```text
Backend Creates Signed URL
```

Step 3:

```text
Client Uploads Directly To R2
```

Step 4:

```text
Backend Creates Upload Document
```

Result:

```text
No File Passes Through Backend Server
```

This significantly reduces server load.

---

# Signed Upload Flow

Recommended approach:

```text
Frontend

↓

↓

Backend

↓

↓

↓
```

# Aggregate Ownership

Uploads owns:

```text
File Metadata

Storage References

Media Lifecycle

Security Metadata

Usage Metadata
```

Uploads does NOT own:

```text
Journey Content

Knowledge Articles

User Profiles

Certificates
```

Those collections only reference Upload IDs.

---

# Collection Cardinality

Expected growth:

```text
Very Large Collection
```

Example:

```text
500 Organizations

10,000 Uploads Each

=

5,000,000 Upload Documents
```

MongoDB Atlas can handle this comfortably with proper indexing.

Storage growth will occur primarily in Cloudflare R2, not MongoDB.

---

# Architectural Rule

Never store:

```text
Base64 Files

Binary Data

Large Media Objects
```

Inside MongoDB.

Always store:

```text
Metadata in MongoDB

Files in Cloudflare R2
```

This is a non-negotiable platform architecture rule.
