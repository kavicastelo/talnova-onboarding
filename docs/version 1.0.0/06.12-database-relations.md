# Talnova Onboarding

# 06.12 — MongoDB Collection Relationships

---

# Organization

Root tenant.

```text
Organization
 ├── Users
 ├── Journeys
 ├── Assignments
 ├── Knowledge Articles
 ├── Uploads
 ├── Notifications
 ├── Audit Logs
 └── System Settings
```

---

# Users

Belongs To:

```text
Organization
```

Referenced By:

```text
Assignments

Notifications

Audit Logs

Uploads
```

---

# Journeys

Belongs To:

```text
Organization
```

Referenced By:

```text
Assignments
```

---

# Employee Assignments

References:

```text
Organization

Journey

Employee
```

Acts as junction collection.

```text
User ← Assignment → Journey
```

---

# Knowledge Base

References:

```text
Organization

Author(User)
```

---

# Uploads

References:

```text
Organization

Uploader(User)
```

Can belong to:

```text
Journey

Knowledge Article

Organization Branding
```

Polymorphic relationship:

```ts
{
 entityType,
 entityId
}
```

---

# Notifications

References:

```text
Organization

Recipient(User)
```

---

# Audit Logs

References:

```text
Organization

Actor(User)
```

---

# System Settings

References:

```text
Organization
```

One-to-one relationship.

---

# Multi-Tenant Rule

Every collection must contain:

```ts
organizationId
```

except:

```text
system collections
```

This guarantees tenant isolation.

---

# Cross Collection Validation

Required checks:

Assignment Creation:

```text
Employee.organizationId
==
Journey.organizationId
```

Upload Attachment:

```text
Upload.organizationId
==
Entity.organizationId
```

Notification Creation:

```text
Notification.organizationId
==
Recipient.organizationId
```

No cross-tenant references allowed.
