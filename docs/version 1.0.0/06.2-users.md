# Talnova Onboarding

# 06.2 — Users Collection

**Collection Name**

```text
users
```

---

# Purpose

The **Users** collection represents every authenticated person in the platform.

A user may be:

* Organization Owner
* Administrator
* HR Manager
* Team Manager
* Employee
* Contractor
* Trainer (Future)

Each user belongs to exactly one organization.

The collection stores:

* Authentication
* Employee profile
* Organization membership
* Permissions
* Preferences
* Employment information
* Dashboard statistics
* Security metadata

    fullName: string,

# Embedded Documents

Embedded because they are tightly coupled to the user:

* Authentication
* Profile
* Employment
* Permissions
* Preferences
* Statistics
* Security

---

# References

Referenced collections:

```text
organizationId → organizations

managerId → users

avatar → uploads
```

Progress is **not stored** inside the user.

Journey progress belongs to the Employee Assignment aggregate.

# Common Query Patterns

Authentication:

```ts
findOne({
  "auth.email": email
})
```

Employee directory:

```ts
find({
  organizationId,
  "employment.status": "active"
})
```

Department employees:

```ts
find({
  organizationId,
  "employment.departmentId": id
})
```

Managers:

```ts
find({
  organizationId,
  "permissions.role": "manager"
})
```

Current user:

```ts
findById(userId)
```

# Repository Responsibilities

UserRepository is responsible for:

* Authentication lookups
* Employee directory queries
* User CRUD
* Department filtering
* Team filtering
* Manager filtering
* User search
* User statistics updates

---

# Service Responsibilities

UserService manages:

* User registration
* Employee invitations
* Password changes
* Role assignment
* Department changes
* Team transfers
* Employment status
* Preference updates
* Security policies

Business rules such as role validation and organization membership are enforced in the service layer.

# Lifecycle

1. User invited.
2. Invitation accepted.
3. Password created.
4. Account activated.
5. Assigned onboarding journeys.
6. Progress tracked through Employee Assignments.
7. Certificates issued after completion.

# Future Extensions

The Users aggregate is designed to support:

* Single Sign-On (SAML/OIDC)
* SCIM provisioning
* Multiple organization memberships
* Profile completion scoring
* AI assistant preferences
* Device management
* Login history
* Session management
* API access tokens
* Custom permission policies

These enhancements can be added without changing the core document structure or breaking existing integrations.
