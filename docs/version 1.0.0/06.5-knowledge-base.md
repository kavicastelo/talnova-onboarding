# 06.5 — Knowledge Base Collection

**Collection Name**

```text
knowledgeBase
```

---

# Purpose

The Knowledge Base collection powers the organization's internal documentation system.

Unlike Journeys, which are structured onboarding experiences with progress tracking, the Knowledge Base is designed for reference material that employees can search and access at any time.

Examples:

* Employee Handbook
* Company Policies
* SOPs (Standard Operating Procedures)
* Benefits Documentation
* IT Setup Guides
* Security Policies
* HR Documentation
* Department Documentation
* FAQ Articles
* Product Documentation
* Internal Wikis

The Knowledge Base acts as the organization's centralized source of truth.

---

# Business Goals

Provide:

* Self-service employee support
* Reduced HR workload
* Reduced manager interruptions
* Centralized documentation
* Searchable organizational knowledge
* Consistent information distribution

# Document Schema

```ts
{
  _id: ObjectId,

  organizationId: ObjectId,

  title: string,

  slug: string,

  summary?: string,

  content: {

    blocks: ContentBlock[]

  },

  categoryId?: ObjectId,

  tags: string[],

  visibility: {

    access:
      "all" |
      "department" |
      "team" |
      "custom",

    departments?: ObjectId[],

    teams?: ObjectId[],

    users?: ObjectId[]

  },

  attachments: Attachment[],

  analytics: {

    views: number,

    uniqueViews: number,

    averageReadTimeSeconds: number,

    lastViewedAt?: Date

  },

  publishing: {

    status:
      "draft" |
      "published" |
      "archived",

    publishedAt?: Date,

    version: number

  },

  searchKeywords: string[],

  createdBy: ObjectId,

  updatedBy?: ObjectId,

  createdAt: Date,

  updatedAt: Date,

  deletedAt?: Date,

  isDeleted: boolean
}
```

# Visibility Rules

Knowledge articles may be restricted.

### Public Within Organization

```ts
{
  access: "all"
}
```

Everyone can access.

---

### Department Restricted

```ts
{
  access: "department",

  departments: [
    ObjectId(...)
  ]
}
```

Only selected departments.

---

### Team Restricted

```ts
{
  access: "team",

  teams: [
    ObjectId(...)
  ]
}
```

Only selected teams.

---

### Custom Access

```ts
{
  access: "custom",

  users: [
    ObjectId(...)
  ]
}
```

Specific employees.





---

# Collection Cardinality

Expected size:

```text
Small to Medium Collection
```

Example:

```text
500 Organizations

1,000 Articles Each

=

500,000 Documents
```

MongoDB Atlas handles this easily.

Primary performance concern is search speed, not document count.

Atlas Search should be considered a core feature from the beginning.
